# Plan: Add RRA Tax Report Tab to Existing Tax Report

## Goal
Add a 4th tab "RRA EBM Submissions" to the existing Tax Report page (`/tax-report`) that shows only orders submitted to RRA, with their receipt numbers, submission status, and tax breakdown. This is the "what RRA sees" view.

## Current State
- **Tax Report**: 3 tabs — by Tax Type, by Date, by Order — all showing tax collected on paid orders
- **RRA EBM module**: Submits orders to RRA API, stores receipts in `rra_ebm_receipt_signatures`, tracks submission status on `orders.rra_ebm_submitted`
- **No connection** between the two — they share the same order data but have zero code linking them

## Files to Modify

| File | Change |
|------|--------|
| `app/Livewire/Reports/TaxReport.php` | Add RRA EBM submission data query + export support |
| `resources/views/livewire/reports/tax-report.blade.php` | Add 4th tab UI + table |

No new files needed — all changes fit within the existing Tax Report component.

## Implementation

### Step 1: TaxReport.php — Add RRA submission data query

Add a new private method `getRraEbmData()` that:
1. Reuses the existing `buildOrdersQuery()` to get paid orders in the date range
2. Filters to only `rra_ebm_submitted = true`
3. Eager-loads `rraEbmReceiptSignature` relation (need to verify this exists on Order model, or join manually)
4. For each order, calculates tax breakdown using existing `processItemTaxes()` and `processOrderTaxes()` methods
5. Returns array of: `{ order, receipt_number, receipt_signature, vsdc_publish_date, invoice_number, tax_amount, tax_breakdown, subtotal, total }`

Since the `rra_ebm_receipt_signatures` table has `order_id` as foreign key, and `orders` may not have a `rraEbmReceiptSignature` relationship defined, we'll do a LEFT JOIN query or use a subquery approach.

The query structure:
```php
$rraOrders = $this->buildOrdersQuery($dateTimeData, ['items.menuItem', 'items.menuItemVariation', 'taxes.tax'])
    ->where('rra_ebm_submitted', true)
    ->leftJoin('rra_ebm_receipt_signatures', 'orders.id', '=', 'rra_ebm_receipt_signatures.order_id')
    ->select('orders.*', 'rra_ebm_receipt_signatures.receipt_number', 'rra_ebm_receipt_signatures.receipt_signature', ...)
    ->get();
```

For each order, compute tax breakdown using the same `processItemTaxes()` and `processOrderTaxes()` methods already in the class.

Also compute RRA-specific summary stats:
- Total submitted orders
- Total tax submitted to RRA
- Total revenue submitted
- Total pending/failed submissions (orders with `rra_ebm_submitted = false` in the date range)

Check if `Module::has('RraEbm')` and `Module::isEnabled('RraEbm')` before querying RRA data. If the module is disabled, either hide the tab entirely or show a "RRA EBM module not enabled" message.

## Data Flow Summary

```
Tax Report (existing)
  → buildOrdersQuery() — gets paid orders in date range
  → processItemTaxes() — computes tax from order_items.tax_breakup
  → processOrderTaxes() — computes tax from order_taxes

New RRA tab
  → Same buildOrdersQuery() + WHERE rra_ebm_submitted = true
  → LEFT JOIN rra_ebm_receipt_signatures
  → Same processItemTaxes() + processOrderTaxes() for tax computation
  → Display receipt_number, invoice_number, vsdc_date from the join
```
